# 跑一张实验票

输入是一张 `wayfinder:task` 票，或一张地图。票的内容已在 wayfinder 讨论时定好：拿到票就开跑，全程无人值守，只在下文「找用户」列出的情形停下。

先用 Skill 工具调用 `server` 与 `records`，之后每一步按它们做。wayfinder 的各项操作（找可开始的票、认领、登记结论）怎么在 GitHub 上做，见 `docs/agents/issue-tracker.md`「Wayfinding operations」。

## 找用户

只有这五种情形停下找用户：

1. 票里写了「先看……再定」这类关口：开跑前停下，把关口要看的东西和你的建议交给用户。
2. 跑到一半发现票的前提不成立。
3. review 发现票里要的东西做不到，或做法与票不一致。
4. 收尾卡住（收尾脚本停下）。
5. 合并需要用户点头。

4、5 两种怎么认、怎么报，见 `/server` 的 closing.md「停下与退出码」。

停下时说清停在哪一步、现场是什么样、你建议怎么办，然后等用户回复；用户回复后从停下的那一步接着做。其余情形（review 的普通问题、启动失败、代码 bug）自己处理完接着走。

## 步骤

每一步做完再进下一步；补收以前没收尾的票时，先查它已经走到哪一步（分支、worktree、实验目录、launch 记录、PR 是否存在、是否已合并），从第一个没完成的步骤接着做。

1. **选票并认领。** 给了票就用它；只给地图时，按 frontier 查询取地图里第一张可开始的 `wayfinder:task` 票，没有就告诉用户并结束。`gh issue edit <票> --add-assignee @me`。
2. **读懂票。** 读票的全文、地图的 Notes（固定设置、判据、本图要调用的技能），按需读相关的已关票和父实验的 Notes。票里有关口时按「找用户」第 1 条停下。
3. **开 worktree、建实验。** 分支名沿用 `<地图简称>-<票号>`（如 `roma-rl-169`）。按 `/server`「流程」开 worktree，按 `/records` 建实验目录（编号取下一个未用的 `E<n>`）。
4. **写配置和代码，提交并推送。** 改共享代码（`runs/` 以外的代码）时按 `CODING_STANDARDS.md` 带测试，测试在服务器 worktree 里跑。本流程内不调用 `/tdd`：它要和用户确认测试接口，会打断无人值守。
5. **review（只在改了共享代码时）。** `git diff --name-only origin/main...HEAD` 里有 `runs/` 以外的文件时，用 Skill 工具调用 `code-review`，固定点 `origin/main`。发现的问题自己改完、提交、推送；只有「找用户」第 3 条的情形才停下。只改了 `runs/<id>/` 的跳过这一步。
6. **开跑。** 按 `/server`「流程」第 4 步启动，用只读命令定时查进度，直到每个方法的 launch 记录都写上了 `end` 与 `status`。启动失败或代码出错，修好、提交后重跑；发现票的前提不成立时按「找用户」第 2 条停下。
7. **写 Notes、评测、检查。** 按 `/records` 写 `runs/<id>/notes.md`，跑 `eval` 和 `check`，直到 `check` 输出「记录无问题」。提交小文件并推送。
8. **开 PR。** 正文几行中文：改了什么、结论在哪份 Notes，加一行 `Closes #<票>`。
9. **收尾。** 按 `/server`「流程」第 6 步运行收尾脚本，直到它走完、最后一行列出可在工作台查看的实验 id。
10. **结论评论。** 在票上发结论评论：先给结论和支撑它的关键数字（指向 `E<n>` 的 Notes 与 PR），末尾一节 `## 建议的下一步` 列出你建议的后续方向。
11. **关票。** PR 合并时 `Closes` 已关票的，核对它已关闭；否则 `gh issue close <票>`。
12. **登记到地图。** 在地图的「Decisions so far」末尾加一行：`- [<票标题>](<票链接>)：<一句话结论>（E<n>）`。

最后对用户说一句「可以在工作台看 E<n> 了」，附一两句结论。

## 范围

本技能只推进这一张票：后续方向只写进结论评论的「建议的下一步」，地图上只加「Decisions so far」这一行。开新票、改地图的「Not yet specified」，由用户在 wayfinder 里决定。
