# RL 建模：当前方案与基础知识

对应票：[RL 建模：两个候选底座上的 state / action / reward，并选定底座](https://github.com/Guochu0-0/moon-exp/issues/6)（地图 [#1](https://github.com/Guochu0-0/moon-exp/issues/1)）。

这份文档有两个用途：

1. 把**已经定下的做法**和**暂定、交给实验的做法**讲清楚，并写明每一项的理由；
2. 补上理解这些决策所需的**基础知识**：LoFTR / RoMa 的内部流程，以及强化学习里用到的那几个概念。

全文用三种标记区分决策状态：

- 【已定】讨论中已经拍板；
- 【暂定】给了默认值，最终由实验决定；
- 【待定】还需要决策。

第 2、3 节是基础知识，已经熟悉的读者可以直接跳到第 4 节。

## 1. 背景：我们要解决什么问题

- **任务**：估计月球光学 patch 与 SAR patch 之间的仿射变换。每对 patch 在数据集构建时已经粗对齐。
- **数据**：训练集**完全没有标注**；Val / Test 带人工点对，只用于评测和选模。
- **起点**：现成的多模态匹配器（AnyMatch-LoFTR、AnyMatch-RoMa）zero-shot 表现是「粗配准可以，精度不够」：
  - Val 上 SR@10 约 85%，SR@3 只有约 30%，AUC@10 约 0.5；
  - 数据见[重跑 baseline，量化 zero-shot 失败模式](https://github.com/Guochu0-0/moon-exp/issues/3)。
- **思路**：在这些预训练权重上做**无标注微调**，把 3 px 以内的精度提上去。
- **为什么用 RL**：配准流水线里有**不可微**的步骤，梯度传不过去：
  - 离散挑选匹配（阈值、互为最近邻、按概率采样）；
  - RANSAC。

  RL（policy gradient）的特点是**打分环节不需要可微**，所以能用「RANSAC 之后的结果好不好」来训练 RANSAC 之前的网络。

  注意：我们的卖点立在「不可微」上，**不是**立在「无标签」上。无标签可以用别的方法解决，比如伪标签，见 2.6 节。

## 2. 基础知识 A：两个底座的内部流程

「底座」指我们在其上做微调的预训练多模态匹配器。

### 2.1 LoFTR：先粗后细，两步都是「在候选里挑一个」

以一对 640×640 的 patch 为例，A 是光学，B 是 SAR。

**① 提特征**

CNN 输出两种分辨率的特征图：
- 粗特征，1/8 分辨率：80×80 = 6400 个格子，每格代表原图 8×8 像素；
- 细特征，1/2 分辨率。

**② 粗匹配**

1. 6400 个格子的特征过 Transformer，让 A 和 B 互相「看」一遍。
2. 算一个 **6400×6400 的相似度矩阵 S**，S[i,j] 表示 A 的第 i 格与 B 的第 j 格有多像。
3. 对 S 做 **dual-softmax**，得到 P[i,j]：
   - 按行 softmax：「A 的第 i 格配 B 的哪一格」的概率分布，每行加起来等于 1；
   - 按列 softmax：反方向的分布；
   - 两者相乘，得到 P[i,j]。只有 i 认为 j 最像、j 也认为 i 最像时，P[i,j] 才大。
4. 推理时，取 P 大于阈值且互为最近邻的 (i,j) 作为粗匹配。**这一步是离散挑选，不可微。**

粗匹配的精度只有 8 px 一格。

**③ 细匹配**

1. 对每个粗匹配，在 1/2 分辨率细特征上，以 B 侧位置为中心截一个 **5×5 窗口**，约覆盖原图 ±5 px。
2. 用 A 侧中心点的特征和这 25 个位置逐一比较，做 softmax，得到 25 个概率。
3. 推理时**不取最大的那个**，而是求**概率加权平均位置**（soft-argmax），得到亚像素坐标。**这一步可微。**

由此推出一个重要性质：**粗级一旦错出一两格，细级窗口就覆盖不到正确位置，救不回来。**

**④ 原始训练怎么监督**

原始训练需要深度加相机位姿真值（MegaDepth），由此知道每个点在另一张图里的真实位置：
- 粗级：让 P 在真值 (i,j) 处尽量大，用 focal loss；
- 细级：让 soft-argmax 的输出接近真值，用 L2 距离。

我们没有真值，这两处监督都用不了。

> AnyMatch-LoFTR 的具体实现（窗口大小、是否为 ELoFTR 式两段细化等）以实际代码为准，**待核对**。

### 2.2 RoMa：给每个像素直接回归「对应点在哪」

RoMa 不挑匹配，而是**对 A 的每个像素直接预测它在 B 中的坐标**。这组坐标叫 warp 或 flow。

**① 粗级**

1. 用 DINOv2 大模型（ViT-L）提特征，分辨率 1/14。
2. 把 B 划成 64×64 = 4096 个**锚点格子**，本库输入下约 8.75 px 一格。
3. 对 A 的每个位置做 **4096 类分类**：它的对应点落在哪个格子里。**这是一个概率分布。**

**② 逐级精修（refiner）**

在 1/8、1/4、1/2、1/1 四个分辨率上依次进行：
1. 按当前 flow 把 B 的特征「搬」到 A 的位置；
2. 与 A 的特征拼接后送入一个小 CNN；
3. CNN **直接输出修正量** Δ，flow ← flow + Δ。

这是**确定性回归，没有概率分布**。**3 px 以内的精度主要在这里决定。**

**③ certainty**

每个像素另外输出一个 0 到 1 的置信度，表示这个像素的 flow 可不可信。遮挡处、无纹理处的置信度低。

**④ 出匹配**

1. 以 certainty 为权重随机抽约 1 万个像素。另有 KDE 平衡，防止抽到的点扎堆。
2. 把这些像素的 flow 当作匹配，送入 RANSAC。

**这一步是随机采样，不可微。**

**⑤ 原始监督**

同样依赖深度加位姿真值：
- 粗级：锚点分类，用交叉熵；
- refiner：flow 与真值的距离；
- certainty：该像素是否真有对应点，用 BCE。

### 2.3 两者对比

| | 自带概率分布的地方 | 决定 3 px 精度的地方 |
|---|---|---|
| **LoFTR** | 粗级 6400×6400、细级 5×5 | 细级 5×5 softmax（**有分布**） |
| **RoMa** | 粗级 4096 类、certainty 采样 | refiner 回归（**没有分布**） |

RL 需要概率分布，而 RoMa 最关键的精修环节恰好没有分布。这是 RoMa 做 RL 更难的根源。

## 3. 基础知识 B：强化学习里用到的概念

### 3.1 三个词

- **policy（策略）**：网络输出的一个**概率分布**。例如 LoFTR 细级那 25 个概率，就是「点落在哪」的 policy。
- **action（动作）**：从 policy 里**抽出来**的一个具体结果，例如抽中第 13 个位置。
- **reward（奖励）**：给这个动作打的分。**打分方法可以是任意黑箱**，比如「跑一遍 RANSAC，看它是不是内点」。

### 3.2 单步（bandit）与多步

- **多步（MDP）**：agent 连续做很多步决策，每步改变状态。例如每步把仿射修正一点点。
- **单步（bandit）**：输入一对 patch，采一次动作，打一次分，结束。

DISK、DaD、RIPE、RIPE++ 全部是单步。

【已定】**我们用单步。** 理由有三：
- 单步直接改造底座自带的分布；
- 理论和工程都最简单，与先例同构；
- 多步方案里，每一步的修正其实都能直接回归，「为什么非用 RL」答不上来。

所以 **state 就是这对 patch 本身**，没有「当前估计」之类的额外状态。

### 3.3 核心公式：policy gradient

目标是让抽到的动作**平均得分**尽量高。可以证明，梯度是：

> **∇ = reward × ∇ log π(抽中的动作)**

用人话说：**抽中了什么，就按它的得分，把它的概率往上推。分高推得多；分为负就往下压。**

玩具例子：一个窗口只有 3 个位置，网络给出的概率是 [0.5, 0.3, 0.2]。

| 这次抽中 | RANSAC 打分 | 效果 |
|---|---|---|
| 位置 1 | +1（内点） | 位置 1 的概率被推高 |
| 位置 3 | −0.1（外点） | 位置 3 的概率被压低 |

抽很多次以后，概率会集中到「总能得高分」的位置。

**关键**：整个过程只需要对 log π 求导，**reward 本身不需要可导**。这就是 RL 能绕过 RANSAC 的原因。

### 3.4 方差与 baseline

**方差**：同样的局面，重复试几次，每次算出的更新方向差别很大。方差大，就要试很多次、用很小的学习率才能学稳，于是训练慢、费算力。

**不减 baseline 时为什么方差大**：假设 reward 是内点数，对同一对 patch 试了三次。

| | reward | 不减 baseline | 减 baseline（95） |
|---|---|---|---|
| 第 1 次 | 80 | +80，往上推 | **−15，往下压** |
| 第 2 次 | 95 | +95，往上推 | 0，不动 |
| 第 3 次 | 110 | +110，往上推 | **+15，往上推** |

- 不减 baseline：三次**都往上推**，有用的信息（第 3 次比第 1 次好）被「大家都是正的」淹没了。
- 减掉 baseline：只剩「比平时好多少」，方向清晰。
- 可以证明，减 baseline 不改变平均意义下的梯度方向，只减少噪声。

类比：baseline 就是「全班平均分」。不知道平均分，就判断不了 80 分该表扬还是批评。

**baseline 的几种算法：**

- **batch 平均**（朴素 REINFORCE 常用）：一个 batch 里所有 patch 对一起平均。缺点是容易的对总高于平均、难的对总低于平均，学到的是「这一对难不难」，而不是「这次做得好不好」。
- **同一对 patch 试 K 次再平均**（GRPO）：只和同一道题的其他答法比，最公平。代价是每对要跑 K 次 RANSAC；网络前向只跑一次，K 次采样共享。
- **另训一个网络来预测平均分**（PPO 的价值网络）：为多步问题设计，对单步问题来说太重。

**RIPE / RIPE++ 为什么不用 baseline 也能训起来**（后半句是我们的推断）：
- 它们的 reward 是逐匹配的（见 3.8 节）；
- 取值在 0、+1、−0.1 附近，天然有正有负、大部分为 0，已经接近「减过平均」的形态。

### 3.5 闭式期望：不抽样也行

如果动作能**全部列举**，并且**每个动作都能单独算出 reward**，就可以不抽样，直接算期望：

> loss = −Σ P(动作) × reward(动作)

- 这样完全没有抽样噪声。
- DISK 的匹配层、RIPE++ 的 LightGlue 匹配器都这么做。
- LoFTR 粗级的 dual-softmax 矩阵 P[i,j] 正好可以这样用。

### 3.6 一个陷阱：闭式期望 + 逐匹配 reward = 伪标签监督

如果 reward(i,j) 的定义是「用这组匹配估出的 RANSAC 仿射来判断 (i,j) 是不是内点」，那么上面的 loss 在数学上就等价于：**拿 RANSAC 结果当伪标签，做普通的监督训练。**

- 这种做法有效。已有非 RL 的工作 **SCENES**（arXiv:2401.10886）就是这样微调 LoFTR 系匹配器的，因此**它必须作为我们的 baseline**。
- 但它**不是 RL 的独特贡献**。

RL 真正不可替代的场景是：**reward 只能对整组动作给出**，拆不到每个匹配头上（见 3.8 节）。

### 3.7 高斯策略：连续动作怎么做 RL

LoFTR 的动作是「在 25 个格子里选一个」，是离散的。RoMa refiner 输出的是连续坐标，没有「选」的过程。

**高斯策略**的做法：
1. 把 refiner 的输出 μ 当作钟形分布（正态分布）的**中心**，再定一个宽度 σ，比如 1 px。
2. 训练时从 N(μ, σ²) 中**抽**一个坐标 a = μ + σ·ε，其中 ε 是标准正态随机数。
3. 按 policy gradient 更新。可以算出 ∇_μ log π(a) = (a − μ)/σ²，于是：

> **μ ← μ + 学习率 × (得分 − 平均分) × (a − μ)/σ²**

也就是：往某方向试，比平时好就往那边挪，比平时差就往反方向挪。

- **直观类比**：蒙着眼找桌上最高的点，每次往随机方向伸手摸一下。
- **σ 的含义**：伸手距离。太大摸不准，太小学得慢；可以固定、逐渐缩小，或者让网络自己学。
- **推理时直接用 μ**，不再试探，网络的用法和原来一样。

### 3.8 逐匹配 reward vs 整对 reward

举一个一维例子：3 个像素的真实位置是 10、20、30，当前输出 μ 是 11、20、29。这次试的结果是 10.2（试好了）、20.9（试差了）、28.5（试差了）。

**逐匹配 reward**：每个像素一张成绩单，比如「离参考位置多远」，参考位置由 RANSAC 仿射给出。

- 像素 1：比平时好，往 10.2 挪 ✓
- 像素 2：比平时差，离开 20.9 ✓
- 像素 3：比平时差，离开 28.5 ✓

一次试验，三个像素都拿到正确的方向。**噪声小。**

**整对 reward**：全组只有一个总分。这次总分比平时差，于是三个像素都往反方向挪。

- 像素 1 **明明试对了，却被队友拖累受罚** ✗

这就是**信用分配问题**。平均下来方向还是对的，但噪声很大。RoMa 一次抽约 1 万个像素，每个像素对总分的影响只有万分之一，噪声会被放大到非常严重。

**为什么还需要整对 reward**：逐匹配 reward 的「参考位置」来自这组匹配**自己估出的**仿射。假设所有匹配**一起**向右偏 4 px，估出的仿射也跟着偏，每个像素离参考位置都很近，**全是满分**。这类「自洽信号」看不见整体偏移。整对 reward 可以用**跨模态的外部标准**，例如按估出的仿射把光学图 warp 过去，看结构是否与 SAR 对得上，从而发现整体偏移。

| | 噪声 | 能否发现整体偏移 | 是否 RL 独特贡献 |
|---|---|---|---|
| **逐匹配 reward** | 小 | 不能 | 否，等价于伪标签（SCENES） |
| **整对 reward** | 大 | 能 | 是 |

整体偏移到底有多严重，由[诊断：3 px 失败是系统性偏移还是随机噪声](https://github.com/Guochu0-0/moon-exp/issues/23)回答。

### 3.9 二值 reward 与分级 reward

- **二值**：误差小于阈值得 +1，否则为外点。问题是误差 0.1 px 和 0.9 px 都得 +1，网络在阈值以内**没有动力变得更准**。
- **分级**：按误差大小给分。RIPE++ 的公式是 r = 1 − ½(d/δ)²，其中 δ = 1；d 超过阈值 τ = 2 时，r = −0.1。

| 误差 d（px） | 0 | 0.5 | 1.0 | 1.41 | 1.8 | 2.0 | >2 |
|---|---|---|---|---|---|---|---|
| 分级 reward | 1.00 | 0.88 | 0.50 | 0 | −0.62 | −1.00 | −0.1 |

- **怪处**：刚好落在阈值内侧的匹配（d=2 时得 −1）比外点（−0.1）罚得还重。
- **RIPE++ 的结果**：默认关闭，加上后 AUC@5 从 54.75 **降**到 52.57。这组数字来自网页抽取，待对照 PDF 复核。
- **我们为什么可能不一样**（推断）：
  - 我们的瓶颈正是阈值以内的精度；
  - 仿射残差是完整的二维距离，而 RIPE++ 的 Sampson 距离只量「离极线多远」。

分级 reward 仍然是自洽信号，看不见整体偏移。

### 3.10 两种正则

- **熵正则**：熵衡量分布有多「摊开」，H = −Σ p log p。

  | 分布 | 熵 |
  |---|---|
  | [0.25, 0.25, 0.25, 0.25] | 1.39（最大） |
  | [0.7, 0.1, 0.1, 0.1] | 0.94 |
  | [1, 0, 0, 0] | 0 |

  - RIPE++ 在每个 8×8 格子的 64 像素 softmax 上**最小化**熵：loss += 1e-6 × H，让定位更尖锐、抽样更稳定。
  - 这一项贡献约 +4 AUC@5；权重增大到 1e-5 性能就变差，1e-4 会训崩。
  - 注意，这和 RL 教科书里常见的「熵奖励」**方向相反**：教科书是最大化熵，用来鼓励探索。
- **KL 锚定**：在 loss 里加一项「当前策略与初始策略的差别」，防止网络为了刷分把原有能力改坏。大模型 RLHF 常用这一项。RIPE++ 是从头训练，所以没有用；我们是在预训练权重上微调，这一项可能更重要。

## 4. 先例对照

| | policy 在哪 | reward | 需要真值？ | 梯度估计 | 降方差 / 正则 |
|---|---|---|---|---|---|
| **DISK** | 检测（格内 softmax×sigmoid）+ 匹配（dual-softmax） | 正确 +1 / 错误 −0.25 / 每点 −0.001 | **要**（深度 + 位姿） | 匹配层闭式期望，检测采样 | 负分退火 |
| **DaD** | 检测（全图 softmax） | 重复性 | **要** | off-policy top-K | 比值归一化 r/E[r]；蒸馏 |
| **RIPE** | 检测（同 DISK），匹配不在 policy 中 | RANSAC-F 内点 +1；负样本对 −1 | 不要 | 单样本 REINFORCE | 无 baseline；**伪标签描述子损失（去掉就训不起来）** |
| **RIPE++** | 检测 + LightGlue 匹配（dual-softmax） | 内点 +1 / 外点 −0.1（检测）；±1（匹配器） | 不要 | 检测单样本；匹配器闭式期望 | 无 baseline；**熵正则**；伪标签描述子损失；「不可匹配」惩罚 |
| **SCENES** | —（非 RL） | RANSAC 几何当伪标签 | 不要 | 可微损失 | — |

RIPE++ 去掉了负样本对，理由有两个：
- 只数内点时，被 RANSAC 滤掉的错误匹配**不受惩罚**；
- 负样本对可能被错标。

它的替代做法是在正样本对内部**给外点负分**。

## 5. 当前方案

### 5.1 已定

| 项 | 决定 | 理由 |
|---|---|---|
| episode 形态 | 单步 bandit，state = patch 对 | 3.2 节 |
| LoFTR 加信号处 | **粗级 dual-softmax + 细级 5×5**，两处都加 | 粗级管外点和大错，细级管 3 px 精度，缺一不可 |
| RoMa 加信号处 | **粗级 4096 类 + certainty 采样 + refiner（高斯策略）**，三处都加 | 粗级错了 refiner 救不回；certainty 决定哪些匹配进 RANSAC；refiner 决定精度 |
| 负样本 | **不用负样本对**；正样本对内部给**外点负分** | 照 RIPE++，见第 4 节 |
| 训练数据 | 训练集无标注；人为施加的随机扰动不算标注 | 地图约束 |

以上都是**起点**，预计实验中会暴露问题，再据实验结果分析、改进。

LoFTR 细级具体用哪种形式，【待定】，需要对照 AnyMatch-LoFTR 的代码再定：
- (a) 从 5×5 离散分布中抽样。训练与推理不一致：推理用的是 soft-argmax。
- (b) 以 soft-argmax 输出为均值的高斯策略。训练与推理一致。

### 5.2 暂定（交给实验）

**算法与方差**

- 逐匹配 reward 部分照 RIPE++：内点正分、外点负分，不减 baseline。LoFTR 粗级这类 dual-softmax 用**闭式期望**，不抽样。
- 整对 reward 部分用 **GRPO 式组内 baseline**：同一对 patch 抽 K 组，K 取小值，约 4。
- 两部分的比重、K 的取值，由实验决定。

**reward 候选集**

候选来自[无标注 reward 候选调研](https://github.com/Guochu0-0/moon-exp/issues/22)：

| 候选 | 类型 | 备注 |
|---|---|---|
| 仿射 RANSAC 内点（二值） | 逐匹配 reward | 等价于伪标签，看不见整体偏移 |
| 仿射残差分级 reward | 逐匹配 reward | 直接瞄准阈值以内的精度；RIPE++ 上无效，需验证 |
| warp 后跨模态结构相似度（CFOG 等） | 整对 reward | 唯一能看见整体偏移的信号；有塌到恒等变换的风险；月面效果未验证 |
| 变换一致性 A₂ = T∘A₁ | 整对 reward | 对纯平移误差没有信号，只作辅助项 |
| 空间覆盖约束 | 附加项 | 防止只在局部纹理区堆匹配 |

调研给出的组合建议（属推断）是：逐匹配分级残差 + 整对级结构相似度 + 覆盖约束。

**正则候选**

权重都交给实验：

- **熵正则（压尖）**：作用在「选位置」的分布上，即 LoFTR 细级 5×5 和 RoMa 粗级 4096 类。权重从 1e-6 量级起步。
- **KL 锚定**：约束网络不要离初始权重太远。
- **伪标签监督项**：RIPE / RIPE++ 都证明**纯 RL 训不起来**，需要一个用 RANSAC 内点当伪标签的监督项兜底。在我们这里，就是 SCENES 式的匹配 / 回归损失。

### 5.3 计算量

原则：**推理零额外开销，训练开销可控。**

- **推理**：所有 RL 部件只在训练时存在。高斯策略推理时直接用 μ；certainty、dual-softmax 的用法都不变。**推理速度与原底座相同。**
- **训练中较便宜的部分**：
  - **闭式期望**只用前向已经算出的 P 矩阵，额外开销是逐元素乘法和一张 reward 矩阵；
  - **仿射 RANSAC** 最小集只有 3 点，迭代次数比 RIPE 的基础矩阵少 1–2 个数量级（按公式估算，未实测），并且可以在 GPU 上批量跑。
- **需要控制的部分：**

| 开销项 | 代价 | 控制方法 |
|---|---|---|
| 组内 baseline 的 K 次采样 | K 次 RANSAC + K 次整对 reward（前向共享） | K 取小值 |
| 变换一致性 | 需要第二次前向，前向次数翻倍 | 只作辅助项，可以隔若干步才算一次 |
| KL 锚定 | 若对输出分布做 KL，需要冻结的初始模型多跑一次前向 | 改用**参数空间锚定**，直接惩罚参数偏离初值（L2-SP），不需要额外前向 |
| RoMa 底座 | 前向本身重（ViT-L + 四级 refiner）；refiner 高斯策略的方差大，可能需要更大的 K | — |

- **仍未知**：本任务分辨率下两个底座的实际显存和吞吐，需要实测。公开的多模态微调大约是 4 张 24 GB 卡跑几个 epoch。

## 6. 两个底座的纸面对比【待定：选哪个】

| 维度 | AnyMatch-LoFTR（半稠密） | AnyMatch-RoMa（稠密） |
|---|---|---|
| policy 来源 | **全部自带**：粗级 dual-softmax、细级 5×5 | 粗级、certainty 自带；**refiner 要新加高斯策略头** |
| 先例 | 粗级 ≈ RIPE++ 匹配器（闭式期望）；细级 ≈ DISK / RIPE 的格内分布 | 无直接先例；高斯策略是通用 RL 做法，但没人用在稠密匹配上 |
| 方差 | 粗级闭式期望，**没有抽样方差**；细级每个粗匹配一个动作（数百至数千） | refiner 每像素一个连续动作（约 1 万个抽样像素），**方差最大** |
| 训练计算 | 较轻 | 重（ViT-L 前向，可能需要更大的 K） |
| 推理计算 | 不变 | 不变 |
| zero-shot 起点 | AUC@10 约 0.5 | 相近 |
| 精度上限 | 细级在 1/2 分辨率上 soft-argmax | 逐像素全分辨率精修，**理论上限可能更高** |
| 已知风险 | 粗级错一两格，细级就救不回 | 信用分配噪声可能导致 refiner 学不动 |

**推荐：选 AnyMatch-LoFTR 作为主底座。**

- 它的每个加信号处都是**自带分布**，并且都有**直接先例**可以照着做；
- 方差和算力都更可控，符合「实验多、算力要省着用」的约束。

RoMa 的优势是精度上限可能更高，但代价是一个无先例、高方差的新部件。在这一点上，一个月的周期经不起试错。

**方法能否迁移到 RoMa**：暂不作为论文主张。等 LoFTR 上的方案跑通以后，再判断是否值得在 RoMa 上复现。

## 7. 已知风险与待验证

- **整体偏移**：如果 3 px 失败主要是系统性偏移，所有自洽类 reward 都碰不到瓶颈。由[诊断票](https://github.com/Guochu0-0/moon-exp/issues/23)回答。
- **reward hacking**：内点数上升但精度不升，RIPE++ 已有实例；以及塌到恒等变换、只在局部区域堆匹配。
- **与 SCENES 的差距**：RL 部分相对纯伪标签方法必须有可测的增益，否则「不可微」的卖点站不住。
- **待复核的数字**：RIPE++ 表 6，以及熵正则权重的描述（论文与表格之间有出入）。
- **待核对的实现细节**：AnyMatch-LoFTR 的细级实现；两个底座的实测显存和吞吐。
